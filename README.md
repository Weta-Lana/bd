## Введение
В современном мире индустрия гостиничного бизнеса играет важную роль в экономике, обеспечивая не только размещение для путешественников, но и широкий спектр дополнительных услуг. Эффективное управление гостиницей требует высококвалифицированного подхода в организации данных, что создаёт актуальность разработки информационных систем для автоматизации процессов. Одним из ключевых компонентов таких систем является база данных, которая позволяет хранить, обрабатывать и анализировать информацию о клиентах, номерах, бронированиях и других аспектах гостиничной деятельности.

Создание базы данных для гостиницы подразумевает не только проектирование структуры хранения данных, но и разработку интерфейсов для взаимодействия пользователей с системой. Это обеспечивает возможность быстрого доступа к информации и управления ею в режиме реального времени, что, в свою очередь, повышает уровень обслуживания клиентов и эффективность работы персонала.

В данной курсовой работе будет рассматриваться проектирование базы данных для гостиницы, включая определение ее предметной области, ключевых объектов, и их взаимосвязей. Кроме того, будет проанализированы основные функциональные требования к системе и рассмотрены возможности автоматизации процессов управления гостиницей через эффективно реализованную базу данных.

Цель работы состоит в создании оптимальной базы данных, позволяющей улучшить процессы бронирования, учёта клиентов и управления номерами, что, в свою очередь, будет способствовать повышению конкурентоспособности гостиничного бизнеса и улучшению клиентского опыта.


## Анализ предметной области. Постановка задачи.
### Описание предметной области и функции решаемых задач.
Предметная область: Система управления гостиницей, включающая управление номерами, клиентами, бронированиями и платежами.

Основные функции, решаемые в рамках задачи:

- Управление клиентами: хранение информации о клиентах гостиницы, их регистрации и контактных данных.

- Управление номерами: регистрация номеров, типов и цен.

- Управление бронированиями: создание, редактирование и удаление бронирований номеров для клиентов.

- Управление платежами: обработка платежей клиентов, включая методы оплаты и сумму платежей.

Задача состоит в автоматизации процесса управления гостиницей с целью упрощения обработки данных и уменьшения ошибок, связанных с ручным ведением учета.

### Перечень входных данных.

Входные данные для системы включают:

#### 1. Данные о клиентах:

- ФИО клиента

- Номер паспорта

- Телефон

- Электронная почта

- Адрес проживания

- Дата регистрации

#### 2. Данные о номерах:

- Номер комнаты

- Тип номера (например, одноместный, двухместный и т.д.)

- Вместимость

- Цена за ночь

#### 3. Данные о бронированиях:

- ID клиента

- ID номера

- Дата заезда

- Дата выезда

- Статус бронирования (например, "подтверждено", "ожидает")

#### 4. Данные о платежах:

- Сумма оплаты

- Дата платежа

- Метод оплаты (например, карта, наличные, перевод)

- Статус платежа (например, "завершено", "в процессе")

### Перечень выходных данных.

Выходные данные системы включают:

#### Список клиентов:
 отображение всей информации о клиентах гостиницы, включая контактные данные и историю бронирований.

#### Список номеров:
 отображение информации о номерах гостиницы, включая статус и цену.

#### Список бронирований:
информация о всех бронированиях, включая статус, данные клиента и номера.

#### Список платежей:
информация о платежах клиентов, включая сумму, метод оплаты и дату.

#### Отчеты по бронированиям:
общее количество бронирований за определенный период, количество занятых и свободных номеров.

#### Отчеты по платежам:
статистика по платежам, включая общую сумму, статус платежей и методы оплаты.

### Ограничения предметной области.

#### Ограничение на количество номеров:
количество номеров в гостинице ограничено физическим количеством комнат. Каждому номеру присваивается уникальный идентификатор.

#### Ограничение на типы номеров:
гостиница может предоставлять различные типы номеров, и каждый тип может иметь свои характеристики (например, цена за ночь, вместимость).

#### Ограничение по времени бронирования:
бронирование должно быть завершено до определенной даты, чтобы избежать наложения на другие бронирования.

#### Ограничение на количество клиентов:
каждый клиент может иметь несколько бронирований, но может быть ограничение на количество активных бронирований для одного клиента.

#### Ограничения на платежи:
система может поддерживать различные способы оплаты, но необходимо учитывать ограничения, связанные с типами методов оплаты.

### Взаимодействие с другими программами.

Система управления гостиницей может взаимодействовать с другими программами через:

#### Платежные системы:
для обработки транзакций и подтверждения платежей. Это могут быть системы, поддерживающие банковские карты, электронные кошельки и другие методы.

#### Системы учета бухгалтерии:
для передачи данных о платежах и доходах в бухгалтерию для дальнейшей отчетности и налогового учета.

#### Электронная почта и SMS-системы:
для отправки уведомлений клиентам о подтверждении бронирования, напоминаниях о дате заезда и выезда, а также о статусе платежей.

#### Системы учета запасов и инвентаря:
для управления запасами гостиничных товаров, таких как постельное белье, полотенца и прочее.

#### Интерфейс с системой онлайн-бронирования:
система может интегрироваться с онлайн-агентами по бронированию для получения данных о новых бронированиях.

Эти взаимодействия помогают интегрировать систему управления гостиницей в более широкую инфраструктуру гостиничного бизнеса и автоматизировать обработку данных.

## Реализация проекта в среде конкретной СУБД.

#### Создание таблиц
```

CREATE TABLE clients (
    id SERIAL PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    passport_number VARCHAR(20) UNIQUE NOT NULL,
    phone VARCHAR(20),
    email VARCHAR(100),
    address TEXT,
    registration_date DATE DEFAULT CURRENT_DATE
);

CREATE TABLE rooms (
    id SERIAL PRIMARY KEY,
    room_number VARCHAR(10) UNIQUE NOT NULL,
    type VARCHAR(50), -- одноместный, люкс и т.д.
    capacity INT NOT NULL,
    price_per_night NUMERIC(10, 2) NOT NULL,
    is_available BOOLEAN DEFAULT TRUE
);

CREATE TABLE bookings (
    id SERIAL PRIMARY KEY,
    client_id INT REFERENCES clients(id) ON DELETE CASCADE,
    room_id INT REFERENCES rooms(id) ON DELETE CASCADE,
    booking_date DATE DEFAULT CURRENT_DATE,
    check_in_date DATE NOT NULL,
    check_out_date DATE NOT NULL,
    status VARCHAR(20) DEFAULT 'Забронировано' -- Забронировано, Отменено, Заселён
);

CREATE TABLE stays (
    id SERIAL PRIMARY KEY,
    booking_id INT REFERENCES bookings(id) ON DELETE CASCADE,
    actual_check_in DATE,
    actual_check_out DATE,
    guests_count INT CHECK (guests_count > 0)
);

CREATE TABLE payments (
    id SERIAL PRIMARY KEY,
    client_id INT REFERENCES clients(id) ON DELETE CASCADE,
    booking_id INT REFERENCES bookings(id) ON DELETE SET NULL,
    amount NUMERIC(10, 2) NOT NULL,
    payment_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    payment_method VARCHAR(50) -- наличные, карта, онлайн
);
```

Получение всех бронирований с клиентами и номерами:

```
SELECT b.id AS booking_id, b.check_in_date, b.check_out_date, b.status AS booking_status,
       c.full_name AS client_name, r.room_number AS room_number, r.type AS room_type
FROM bookings b
JOIN clients c ON b.client_id = c.id
JOIN rooms r ON b.room_id = r.id;
```

```
UPDATE clients
SET phone = '89990007788'
WHERE id = 1;
```

Удаление бронирования:

```
DELETE FROM bookings
WHERE id = 1;
```

## Разработка стратегии резервного копирования базы данных

#### Типы резервных копий:

- Полные резервные копии: создаются еженедельно для всего содержимого базы данных.

- Инкрементальные копии: создаются ежедневно, чтобы сохранять только изменения с последнего резервного копирования.

#### Частота копирования:

- Полное резервное копирование — каждую неделю.

- Инкрементальное копирование — каждый день (например, в ночное время).

#### Реализация:

Использовать встроенные инструменты PostgreSQL для создания резервных копий:

- pg_dump — для создания резервных копий базы данных.

- pg_basebackup — для создания физической резервной копии базы данных.

#### Пример для полного резервного копирования с помощью pg_dump:

```
pg_dump -U username -F c -b -v -f /path/to/backup/db_backup.sqlc dbname
```

#### Хранение резервных копий:

- Хранить резервные копии на отдаленном сервере или в облачном хранилище для безопасности.

#### Восстановление данных:

```
pg_restore -U username -d dbname /path/to/backup/db_backup.sqlc
```
